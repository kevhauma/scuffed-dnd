# TICKET-DX-07 — Three roots: `client/`, `server/`, `shared/`

- **Area:** Tooling, test infrastructure, and convention adoption
- **Type:** Refactor
- **Traceability:** v3 [Req 50](../requirements.md#requirement-50-source-tree-separation),
  [Req 51.2](../requirements.md#requirement-51-enforced-architecture-rules); overview
  [D14](../overview.md#d14--three-roots-client-server-shared),
  [D5](../overview.md#d5--the-engine-is-the-shared-kernel-and-the-server-is-authoritative)

## User story

As a developer, I want the frontend and the backend to be visibly separate parts of the repository
rather than folders that happen to sit beside each other, so that the boundary is a structure rather
than a habit.

## Description

**The first ticket of the milestone**, before a single line of server code exists. Numbered DX-07 but
built first — the v2.0 precedent of DX-05 taken early and DX-04 last, where the number records the
area and the position records the dependency.

It has to be first because it is a pure move of the *existing* tree. Every ticket after it adds
files; doing this afterwards would mean moving twice as much, twice as riskily, with a half-built
server in the way.

**No behaviour changes here.** Same test count before and after, or the ticket is not done.

## Current situation (as-is)

- `src/` is one flat set of layers — `types/`, `engine/`, `services/`, `stores/`, `components/`,
  `routes/` — and [SRV-01's first draft](./TICKET-SRV-01-server-layer-and-kernel-boundary.md) would
  have added `server/` as a seventh sibling, saying by its position that a database module and a
  button are the same kind of thing.
- `src/routeTree.gen.ts` is generated by the TanStack Router plugin from a configured routes
  directory, and is **never hand-edited**.
- `package.json` declares `"#/*": "./src/*"`, and [CLAUDE.md](../../../CLAUDE.md) says it "exists but
  is unused — don't half-adopt it". Every import in the tree is relative.
- `vite-tsconfig-paths` is already a devDependency, so `tsconfig` path mappings already reach both
  Vite and Vitest — the aliases below cost no new plumbing.
- **`services/` mixes two kinds of code**, and nothing has forced the issue yet:
  `validateConfigurationShape`, `RETIRED_FIELDS`, the `SchemaVersionError`/`ValidationError` classes
  and `references.ts`'s stored↔display translation are pure, while `storage.ts`'s LocalStorage access
  and `exportConfiguration`'s `Blob`/download helpers are browser-only.

## Desired result (to-be)

- Three roots and nothing else under `src/`: `shared/` (the Kernel — `types/` + `engine/`, importing
  neither sibling), `client/` (`components/`, `routes/`, `stores/`, and the browser half of
  `services/`), `server/` (empty but real, with its README stating the rule SRV-01 fills it under).
- **`services/` split along the seam that was always there**: shape validation, retired-field
  refusal, import semantics and the stored↔display formula translation move to `shared/`, where
  RUL-01, RUL-02 and IO-04 will reuse them; LocalStorage, `Blob` and the download helpers stay in
  `client/`. Nothing is duplicated.
- Cross-root imports go through `#shared/*`, `#client/*` and `#server/*`, with **dependency-cruiser**
  enforcing the root boundary in `yarn run check` and the pre-commit hook, and the production build
  proving separately that no `server/` module reaches the client bundle.

## Notes

- **Do the move and the alias adoption in one commit, and nothing else in it.** Both touch every
  file; separating them doubles the review surface for no benefit, and mixing anything substantive in
  makes the diff unreviewable. If something *must* change to compile, note it explicitly rather than
  letting it ride along.
- **The alias adoption reverses a standing rule**, deliberately (D14). Relative imports are fine
  within a root and stay; what changes is that a crossing is spelled `#shared/engine/calculator`, so
  the boundary is legible at the import line and checkable by prefix rather than by counting `../`s.
  This is the one change where rewriting every import costs nothing, because they are all moving
  anyway.
- **The `services/` split is the ticket's only judgement call**, and it is the useful one. The seam
  is "does this touch a browser API": `localStorage`, `Blob`, `URL.createObjectURL` and the anchor
  click stay client-side; everything that merely reasons about a `Configuration` is shared. If a
  function does both, split the function — do not put it in `client/` and have the server reimplement
  it, which is the duplication D5 exists to prevent.
- The wider architecture rules — store-owned persistence, repository-owned queries, UI primitives as
  leaves — are **TICKET-DX-08**. This ticket installs the tool and lands the root boundary only, so
  that a failure here is unambiguously about the move.

## What the review changed

The `conventions-reviewer` pass found one real hole and several stale references. Recorded here
because the first one is the kind of mistake DX-08 could repeat:

- **The fixture exemption was on the wrong axis.** `options.exclude` took the `boundaryFixtures/`
  modules out of the graph entirely, which stopped them being *violators* and also stopped them
  being *destinations* — so a real client module importing `#server/boundaryFixtures/target` passed
  `yarn run check`. Fixed by moving the exemption to `from.pathNot` on every rule, and proven by
  probe: with the import added to `router.tsx`, `depcruise` now reports
  `no-client-to-server: src/client/router.tsx → src/server/boundaryFixtures/target.ts`.
  **The lesson for DX-08: exempt a fixture as a source, never by excluding it.**
- **`tsPreCompilationDeps` was asserted in a comment, not by a fixture.** Every fixture used a value
  import, so the option could have been flipped off with all tests still green.
  `server/boundaryFixtures/reachesClientTypeOnly.ts` now closes it.
- **The fourth-root guard was one-sided**, so `client-reaches-only-shared` joins
  `server-reaches-only-shared`. D14 calls the rule symmetric; it is now symmetric in the config too.
- **`architecture/` was outside Biome's `files.includes`**, so this ticket's own 110-line test was
  neither linted nor formatted by the check it was written to support.
- Stale references fixed: the `conventions-reviewer` agent still told reviewers to *flag* an alias
  import; `vitest.config.ts`, the **project-map** skill's `tanstackStart` snippet, the styles README
  and `src/server/README.md`'s link all named the old tree or the wrong extension. `ONBOARDING.md`
  had been silently normalised CRLF→LF by the codemod and was restored, so its diff is content only.

**One suggestion was declined.** `exportConfiguration` has no production caller outside
`configFiles.ts` and could be made module-private. It stays exported because TICKET-IO-04 —
"upload this browser's ruleset to your account" — needs exactly a serialised body, and narrowing
the surface now to widen it in three tickets is churn rather than discipline.

**Two findings were left as pre-existing**, neither introduced here: `fallow` sits in
`dependencies` rather than `devDependencies`, and `scripts/*.mjs` is outside Biome's includes.
