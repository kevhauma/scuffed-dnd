# TICKET-CST-02 — Constants panel

- **Area:** Constants configuration
- **Type:** Feature
- **Traceability:** Concept [05 · Constant](../../excel%20export%20summary/concepts/05-constant.md) (editor requirements)

## User story

As a User, I want a Constants section in configuration mode showing each constant with where it's
used, so tuning a balance lever is one edit with its blast radius visible.

## Description

The UI for TICKET-CST-01's entity, following the established config-domain shape.

## Current situation (as-is)

- CST-01 lands the entity, resolution, and seeds with no editor; the config dashboard
  ([`ConfigDashboard`](../../../src/components/config/dashboard/)) has no constants card and no
  route exists.

## Desired result (to-be)

- A Constants panel at `/config/constants` in the standard four-part shape
  (`ConstantsConfigPanel` / `ConstantCard` / `ConstantFormDialog` / `useConstantManager`), plus
  the dashboard card and nav entry.
- Each card shows the constant's value, description, and **where it's used** (reverse index from
  REF-01's machinery — the spec's editor requirement).
- Delete goes through REF-02's guarded action; the dialog renders the reference list.

## Implementation notes (2026-08-07)

1. **The identifier rule is now enforced in both places CST-01 said it had to be.** That ticket's
   implementation note 4 flagged the gap: `^[a-z][a-z0-9_]*$` and name-uniqueness were checked by
   `validateConfiguration` for untrusted import, but there was no form. `useConstantManager`'s save
   path is that form's half — a bad or duplicate identifier sets a field error and the dialog stays
   open, so nothing reaches the store. The two checks are deliberately not shared code: one guards
   a parsed file, the other a live form, and they report differently.
2. **The usage list is the reverse index, not a new mechanism.** `findReferences({kind:'constant'})`
   already existed from REF-02 — this ticket only surfaces it, built once per configuration in a
   `useMemo` and handed to each card as a prop. `characters` is deliberately not passed: no
   character field can name a constant, only a configuration formula can.
3. **The panel joined an existing seven-way duplication family**, not a new one. The
   `if (!config) …` guard plus the header card is byte-identical across every config panel;
   fallow reports the new panel as six "introduced" clone groups whose other members are all
   pre-existing. Extracting a shared preamble is a cross-domain refactor of seven panels and
   belongs in its own ticket, not here.
